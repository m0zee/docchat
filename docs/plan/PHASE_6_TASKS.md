# Phase 6 tasks: workspaces, API keys and the public API

Branch `phase-6` from `main`, draft PR into `main`. One commit per task. `composer ci:check` must pass after every task. Every external API is faked in tests. Design notes: [TENANCY_REVIEW.md](TENANCY_REVIEW.md).

- [x] **P6-1 Workspaces schema.** Migrations for `workspaces` (name, slug unique, settings jsonb) and `workspace_user` (role owner/member, unique pair), `users.current_workspace_id`. Models `Workspace` (members, owners, documents, conversations), enum `WorkspaceRole`, factory. `User::workspaces()`, `currentWorkspace()`, `switchWorkspace()`. Registration and the sample seeder create a personal workspace. Tests.
- [x] **P6-2 workspace_id on data.** Add `workspace_id` to documents, chunks, conversations, messages; make `user_id` nullable (null on delete). Backfill one workspace per existing user inside the migration. Indexes. Tests for the backfill.
- [x] **P6-3 Scoping.** `CurrentWorkspace` service, `BelongsToWorkspace` trait (global scope when a workspace is set, fills `workspace_id` on create), web middleware. Move Retriever, AnswerService, DocumentService, IngestDocumentJob, EvalRunner and `docchat:eval` (`--workspace`) to workspaces. Chunks inherit `workspace_id`. Policies by membership and role. Update factories and existing tests.
- [x] **P6-4 Workspace switcher.** Sidebar switcher, create workspace, rename (owner). Dashboard shows the current workspace. Web isolation tests: a member of A gets 403/404 on B's documents, chats and citations.
- [x] **P6-4b Members and invites.** Workspace settings page (owner): list members with roles, change role, remove (never the last owner), add an existing user by email, or invite by email. `workspace_invitations` (email, role, token hash, invited_by, expires in 7 days, accepted_at). `WorkspaceInvitation` mail with the join link, also shown to copy. `/invitations/{token}`: signed-in users accept; guests register or log in first and come back. Members can leave. Default mailer stays `log` (free); deploy.md lists free SMTP options. Tests.
- [x] **P6-5 Document sources.** `source` enum, `external_id`, `meta` jsonb, `content_hash`, unique (workspace_id, source, external_id). Re-upload with the same external_id replaces the file and re-ingests with the same id; same hash skips embedding. Tests.
- [x] **P6-6 Conversation channels.** `channel` enum and `external_id`, unique (workspace_id, channel, external_id). `Conversation::forChannel()` finds or creates. Tests.
- [x] **P6-7 API keys.** `api_keys` table and model, `dc_live_` keys (prefix + SHA-256 hash), abilities, allowed_origins, rate_limit_per_minute, last_used_at, revoked_at. Settings page: create (shown once), list, revoke. API middleware: bearer auth, ability check, per-key RateLimiter with 429 + Retry-After. Consistent JSON error format. Tests.
- [x] **P6-8 Usage events.** `usage_events` table, recorded by AnswerService (question) and IngestDocumentJob (ingest, embedding token estimate). Monthly usage page with totals per channel. Tests.
- [x] **P6-8b Token-saving cache (Moiz, 2026-11-24).** No new packages and no paid services: Laravel's database cache plus a Postgres table.
  - *Query embeddings:* cached by sha256(embedding model + normalized question) for 30 days, so a repeated question costs no Gemini call.
  - *Answers:* `answer_cache` table (workspace_id, normalized question hash, question embedding, document-scope hash, answer, citations, corpus_version, hits, last_hit_at, expires_at). An exact match on hash + scope is tried first. Then comes a semantic match with pgvector cosine similarity ≥ `docchat.cache.semantic_threshold` (default 0.95), in the same workspace and scope. Only first questions in a conversation are cached, because a follow-up depends on the chat history. Refusals and errors are never cached.
  - *Invalidation:* each workspace has a `corpus_version` that goes up when a document becomes ready, is re-ingested or is deleted. Older cache rows stop matching and are pruned on a schedule. The default TTL is 7 days.
  - *Usage:* `usage_events.cache_hit` (exact / semantic / none), with tokens saved estimated from the original answer. The usage page shows the hit rate and tokens saved per channel, and the web usage line says "from cache".
  - Config switch `DOCCHAT_ANSWER_CACHE=true`, plus a per-workspace off switch in settings. A cached answer streams out the same way on SSE, the widget and bots. Tests: exact hit, semantic hit, a miss under the threshold, a miss after a document changes, a miss across workspaces and document scopes, and no caching for follow-ups or refusals.
- [x] **P6-9 Documents API.** `POST/GET /api/v1/documents`, `GET/DELETE /api/v1/documents/{id}`, filters `source` and `external_id`, API resources. Tests incl. cross-workspace isolation.
- [x] **P6-10 Ask API and formats.** `POST /api/v1/ask` (question, document_ids, channel, external_conversation_id, format) returning answer, citations, conversation_id, usage. `MessageFormatter` for plain, markdown, telegram_html, whatsapp with channel-safe splitting. Tests.
- [x] **P6-11 SSE stream.** `GET|POST /api/v1/ask/stream` with `token` events and a final `done` event (citations, usage, conversation_id) and an `error` event. Tests for the stream shape.
- [x] **P6-12 Outgoing webhooks.** `webhooks` table, settings page, `SendWebhookJob` with backoff, `X-DocChat-Signature: sha256=<hmac>` and `X-DocChat-Timestamp`, payload with meta. Fired on document.ready / document.failed. Receiver-side replay check documented. Tests for signing and retries.
- [x] **P6-13 API docs.** `dedoc/scramble` at `/docs/api`, with examples on requests and responses. Test that the page and spec render.
- [x] **P6-14 Docs and handoff.** README: architecture diagram (Laravel core + n8n + channels), API quick start, security notes. Handoff file.
